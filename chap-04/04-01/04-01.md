# 04-01

Considere a seguinte consulta SQL, que visa a achar uma lista de títulos de todos os cursos ministrados na primavera de 2017 juntamente com o nome do instrutor.

<pre>
<b>select</b> nome, título
<b>from</b> instrutor
<b>natural join</b> ministra
<b>natural join</b> seção
<b>natural join</b> curso
<b>where</b> semestre = 'Spring' <b>and</b> ano = 2017
</pre>

O que há de errado com essa consulta?

## Resposta

A consulta está sintaticamente correta, e pode ser escrita da seguinte maneira ([04-01-1.sql](/lab/dbt_/models/chap-04/04-01/04-01-1.sql)):

```sql
select
    name,
    title
from
    instructor
    natural join teaches
    natural join section
    natural join course
where
    semester = 'Spring'
    and year = 2017;
```
| name   | title                     |
| ------ | ------------------------- |
| Brandt | Game Design               |
| Brandt | Game Design               |
| Kim    | Intro. to Digital Systems |


No entanto, vamos analisar cuidadosamente os nomes das colunas de cada uma das tabelas envolvidas ([04-01-2.sql]()):

```sql
select
  table_name,
  column_name
from
  information_schema.columns
where
  table_name in ('instructor', 'teaches', 'section', 'course')
order by table_name asc
```
| table_name | column_name  |

| instructor | name         |
| instructor | dept_name    |
| instructor | salary       |
| instructor | id           |
| teaches    | course_id    |

Vamos remover todas as colunas que **não** são utilizadas pelo **natural join** do resultado acima, para facilitar a visualização das colunas relevantes para essa operação.

| table_name | column_name  | 
| ---------- | ------------ |
| instructor | dept_name    | (4)
| instructor | id           | (1)
| teaches    | course_id    | (2)
| teaches    | sec_id       | (3)
| teaches    | id           | (1)
| section    | course_id    | (2)
| section    | sec_id       | (3)
| course     | course_id    | (2)
| course     | dept_name    | (4)


Note que há quatro atributos que permitem a associação das tabelas envolvidas nessa operação através do **natural join**:

1. <em><b>instructor.id</em></b> = <em><b>teaches.id</em></b>
2. <em><b>teaches.course_id</em></b> = <em><b>section.course_id</em></b> = <em><b>course.course_id</em></b>
3. <em><b>teaches.sec_id</em></b> = <em><b>section.sec_id</em></b>
4. <em><b>instructor.dept\_name</em></b> = <em><b>course.dept_name</em></b>

Em particular, podemos notar que a coluna <em><b>nome_dept</b></em> existe nas relações <em><b>instrutor</em></b> e <em><b>curso</b></em>. Portanto, essa consulta retorna os casos em que instrutores ministram seções de curso cujo departamento da disciplina é o mesmo departamento do instrutor.

Para tornar essa consulta mais geral, podemos usar a cláusula <b>using</b>. Com isso, sejam relações $r_1$ e $r_2$, a consulta retornaria os casos em que $r_1.A_1$ = $r_2.A_1$
e $r_1.A_2$ = $r_2.A_2$, mesmo que haja um atributo $A3$
no qual $r_1.A_3 \neq r_2.A_3$.

Vejamos como aplicar essa cláusula através da consulta a seguir:
```sql
select
    name,
    title
from
    instructor
    natural join teaches
    natural join section
    natural join course
where
    semester = 'Spring'
    and year = 2017;
```
