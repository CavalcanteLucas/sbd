# 03-03

Escreva as seguintes inserções, exclusões e atualizações em SQL usando o esquema da universidade.

**a)** Aumente o salário de cada instrutor do departamento Comp. Sci. em 10%.

**b)** Exclua todos os cursos que nunca foram oferecidos (ou seja, não ocorrem na relação $seção$).

**c)** Insira cada aluno cujo atributo $\text{tot}\_\text{cred}$ é maior que 100 como um instrutor no mesmo departamento, com um salário de $10.000.

## Resposta

Lembre-se de que as consultas de **inserção**, **exclusão** e **atualização** modificam o banco de dados permanentemente (essas são operações não-idempotentes). Por essa razão, é importante verificar o estado dos dados *antes* de executar esse tipo de consulta. Utilizaremos um sinal de alerta [**!**] para indicar consultas desse tipo.

Além disso, para responder questões que exigem alteração do banco, serão apresentadas consultas equivalentes alternativas, onde os resultados esperados são materializados em novas tabelas, evitando que o conteúdo ou a estrutura da tabela original sofram mudanças.

Com isso, queremos evitar a todo custo a situação em que devemos restaurar o banco de dados a uma versão anterior. Esse tipo de operação pode ser muito custosa para um SBD em produção. Sobretudo, há uma potencial perda de informações para atualizações realizadas entre a data do último backup e o completo re-estabelecimento do serviço.



### a)

Vejamos como estão os salários antes da atualização, através da consulta a seguir ([03-03-a1.sql](../dlab/dbt_/models/chap-03/03-03/03-03-a1.sql)):

```sql
select *
from instructor
where dept_name = 'Comp. Sci.'
```
| id    | name       | dept_name  | salary   |
| ----- | ---------- | ---------- | -------- |
| 10101 | Srinivasan | Comp. Sci. | 65000.00 |
| 45565 | Katz       | Comp. Sci. | 75000.00 |
| 83821 | Brandt     | Comp. Sci. | 92000.00 |

Agora, podemos realizar a consulta de atualização ([**!**][03-03-a2.sql](../dlab/dbt_/macros/chap-03/03-03/03-03-a2.sql)):

```sql
update instructor
set salary = salary * 1.1
where dept_name = 'Comp. Sci.'
```

e executar a primeira consulta ([03-03-a1.sql](../dlab/dbt_/models/chap-03/03-03/03-03-a1.sql)) novamente, para verificar os salários após a atualização.

Alternativamente, podemos declarar o resultado esperado sem modificar a tabela original, como através da consulta a seguir [03-03-a3.sql](../dlab/dbt_/models/chap-03/03-03/03-03-a3.sql):

```sql
select
    id,
    name,
    dept_name,
    salary * 1.1 as salary
from
    instructor

    dept_name = 'Comp. Sci.'
```

Podemos selecionar esses alunos através da seguinte consulta ([03-03-c1.sql](../dlab/dbt_/models/chap-03/03-03/03-03-c1.sql)):


No entanto, não é possível torná-los instrutores com esses salários.

Se tentarmos executar a seguinte consulta ([**!**][03-03-c2.sql](../dlab/dbt_/macros/chap-03/03-03/03-03-c2.sql)):

```sql
insert into instructor
select s.id, s.name, s.dept_name, 10000.00 as salary
  from student s
  where tot_cred > 100
```

nos deparamos com um erro:


> There was a problem!
> 
> new row for relation "instructor" violates check constraint "instructor_salary_check"
> You need both a title, and some query text.


Podemos buscar na tabela `pg_contraint` por restrições de integridade[^1] com o nome `instructor_salary_check` (veja a consulta [03-03-c3.sql](../dlab/dbt_/models/chap-03/03-03/03-03-c3.sql)):

```sql
select conname, pg_get_constraintdef(oid)
  from pg_constraint
  where conname like 'instructor_salary_check';
```
| conname                 | pg_get_constraintdef                |
| ----------------------- | ----------------------------------- |
| instructor_salary_check | CHECK ((salary > (29000)::numeric)) |

Com isso, vemos que a tabela `instructor` possui uma restrição para garantir que nenhum instrutor possa receber menos que $29000.00.
